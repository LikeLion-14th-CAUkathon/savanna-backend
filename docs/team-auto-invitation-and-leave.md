# 팀 생성 시 초대 링크 자동 발급과 팀 탈퇴

## POST /api/v1/teams

팀 저장 → 생성자 LEADER 등록 → 영구 초대 링크 저장을 같은 트랜잭션으로 처리합니다. 링크 생성 실패 시 팀·팀원·초대 레코드가 모두 롤백됩니다. 기존 한 계정 한 팀 제한은 유지합니다.

성공은 기존처럼 201이며 `data.inviteUrl`을 추가합니다.

```json
{
  "status": 201,
  "message": "팀 생성 성공",
  "data": {
    "teamId": 1,
    "name": "사바나 팀",
    "role": "LEADER",
    "photoUrl": null,
    "inviteUrl": "https://savanna-frontend.vercel.app/invite/예시-토큰"
  }
}
```

URL은 서버의 기존 TEAM_INVITATION_URL_TEMPLATE 정책을 따릅니다. 프런트가 window.location.origin으로 새 주소를 만들지 않습니다. 팀 생성 성공 후 별도의 초대 생성 POST를 호출할 필요가 없습니다.

이후 `GET /api/v1/teams/{teamId}/invitations/current`에서 팀원 누구나 같은 URL을 다시 조회합니다. 기존 초대 생성 POST도 남겨 두며 활성 링크가 있으면 재사용합니다. 과거에 만들어져 링크가 없는 팀이나 링크 폐기 후에는 기존 생성 API로 발급할 수 있습니다. 기존 실제 DB 팀을 자동 수정/백필하지는 않습니다.

## DELETE /api/v1/teams/{teamId}/members/me

Bearer 인증이 필요하며 요청 body는 없습니다. 본인의 소속만 제거합니다. 다른 사람을 탈퇴시키는 API가 아닙니다.

```javascript
await api.delete(`/api/v1/teams/${teamId}/members/me`);
```

```json
{
  "status": 200,
  "message": "팀 탈퇴 성공",
  "data": {"teamId": 1, "userId": 2, "newLeaderUserId": null, "teamDeleted": false}
}
```

일반 팀원 탈퇴는 newLeaderUserId가 null입니다. 팀장이 탈퇴하면 남은 팀원 중 joinedAt 오름차순, 시각이 같으면 teamMemberId 오름차순으로 가장 먼저 가입한 사람을 LEADER로 승계합니다. 승계와 탈퇴를 같은 트랜잭션으로 처리하고 newLeaderUserId에 새 팀장 사용자 ID를 반환합니다. 기존 초대 링크는 변경하지 않습니다.

마지막 한 명도 200으로 탈퇴합니다. 같은 트랜잭션에서 팀·팀원 소속·초대·추천·원정·제안·수신/응답·일정·체크리스트·단계 이력을 실제 삭제합니다. 이때 teamDeleted=true, newLeaderUserId=null입니다. 사용자 계정, 공유 공고, 다른 팀 데이터는 보존합니다. 삭제된 초대 링크는 404입니다.

| 상태 코드 | 의미 |
|---|---|
| 200 | 탈퇴 및 필요한 팀장 승계 완료 |
| 400 | 잘못된 팀 ID |
| 401 | 로그인 필요 |
| 403 | 해당 팀 소속 아님(탈퇴 후 재요청 포함) |
| 404 | 팀 없음 |


## 탈퇴 후 데이터와 권한

- 팀원이 남아 있으면 TeamMember 소속만 제거하고 사용자·팀·공고·원정·제안·제안 수신/응답 기록은 보존합니다.
- 팀원이 남아 있으면 JOINED를 DECLINED로 바꾸거나 응답 시각·읽음 시각·응답 버전을 변경하지 않습니다. 제안 응답과 팀 탈퇴는 별개입니다.
- B03 제안 응답 집계는 기존 제안 수신 기록의 응답 이력입니다. D01 원정 지도 joinedCount는 현재 팀 소속이며 JOINED인 수신자만 집계하므로 탈퇴자를 제외합니다.
- 탈퇴 후 팀 상세·현재 초대 링크·원정 접근 권한은 사라집니다. 팀원이 남아 있으면 기존 정책에 따른 개인 제안 이력은 삭제하지 않습니다. 마지막 탈퇴 시 해당 팀의 모든 제안 이력도 삭제합니다.
- 팀장 승계 후 새 팀장이 팀 수정·초대 관리·사진 업로드 권한을 가집니다. 이전 팀장은 더 이상 팀장 권한을 갖지 않습니다.
- 탈퇴한 계정은 다른 팀 생성 또는 초대 가입이 가능합니다. 사용자 잠금과 팀 잠금을 사용해 기존 한 계정 한 팀 제한과 함께 처리합니다.

프런트는 성공 후 내 팀 목록/팀 상세/원정/알림 등 팀 관련 캐시를 재조회하거나 제거하고 미소속 화면으로 이동합니다. teamDeleted는 필수 boolean이며 마지막 탈퇴에 true, 그 외 false입니다. newLeaderUserId는 승계가 없으면 필드를 생략하지 않고 null입니다. 팀 생성 성공 시 반환받은 inviteUrl로 바로 공유 UI를 표시합니다.

## 배포·검증

새 DB 컬럼/마이그레이션은 필요하지 않습니다. 기존 role·joinedAt 필드를 사용합니다. EC2와 실제 로컬 앱 DB는 이번 작업에서 변경하지 않습니다. 새 JAR 배포 및 Swagger 새로고침이 필요합니다.

자동 테스트는 메모리 DB에서 링크 자동 생성/재조회/재사용, 링크 실패 시 전체 롤백, 일반 탈퇴와 다른 팀 생성, 팀장 자동 승계·동률 처리·권한 전환, 마지막 팀원 자동 삭제와 다른 팀·공유 공고 보존, 응답 이력 보존·현재 합류 인원 감소, Swagger 응답 스키마를 검증합니다.

검증 결과: 전체 실행에서 215개 통과. 추가 롤백 테스트의 Mockito 프록시 설정 오류를 수정하고 단독 재실행해 1개 통과했습니다(총 216개 검증). 컴파일 및 bootJar 성공. 실제 앱 DB 및 EC2는 변경하지 않았습니다.

팀 사진의 S3 객체 파일은 자동 삭제하지 않습니다. 현재 IAM 역할은 PutObject/GetObject만 있으며 DB 삭제와 S3 삭제는 원자적으로 처리되지 않습니다. 별도 파일 정리 정책과 DeleteObject 권한이 필요합니다. DB의 객체 키 참조는 팀과 함께 삭제됩니다.
