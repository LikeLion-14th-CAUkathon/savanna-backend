# D02 인원 제한 안내

개인 참가 공고도 일반 목록과 추천 후보에 유지합니다. 팀 전체 인원, 최소 인원 미달, 인원 미확인을 이유로 공고를 제외하거나 `MEMBER_COUNT` 조건을 반환하지 않습니다. 다른 참가 조건과 공개·접수 상태 정책은 유지합니다.

`GET /api/v1/expeditions/{expeditionId}` 응답에 다음 필드가 추가됩니다. 단계·일정 변경 응답도 동일한 원정 응답 형식을 사용합니다.

```json
{
  "joinedCount": 2,
  "memberCountNotice": "현재 6명이 합류했어요. 최대 5명까지 참가할 수 있어요."
}
```

- `joinedCount`: 해당 원정의 현재 팀 소속 `JOINED` 수신자의 고유 인원입니다. 기존 D01 집계처럼 발신자·미응답·거절·탈퇴자는 제외하고, 여러 제안에 중복으로 응답한 사용자는 한 번만 셉니다.
- `memberCountNotice`: 확인된 최대 인원 초과 시 `현재 N명이 합류했어요. 최대 M명까지 참가할 수 있어요.`, 확인된 최소 인원 미달 시 `현재 N명이 합류했어요. 최소 M명이 필요해요.`를 반환합니다. 범위 내이거나 해당 제한 미확인이면 명시적으로 `null`입니다.
- 개인 참가로 최대 인원이 1인 공고는 합류 인원이 2 이상일 때 안내합니다. 최대 인원 미확인은 0명이나 무제한으로 간주하지 않습니다. 최소 인원이 3명이고 합류 인원이 2명이면 `현재 2명이 합류했어요. 최소 3명이 필요해요.`를 안내합니다.
- 안내는 정보 표시용입니다. 응답 변경이나 원정 진행을 막지 않습니다. 프런트는 D02에서 이 문구가 null이 아닐 때만 표시하고, 공고 참가 조건 응답의 기존 `MEMBER_COUNT`를 이용한 인원 안내는 제거해야 합니다.

DB 스키마 변경이나 데이터 재수집은 필요하지 않습니다. 이미 저장된 추천에서 인원 때문에 빠진 공고는 추천 재생성 후 새 후보로 포함될 수 있습니다. 추천 순위·개수와 다른 필터에 따라 모든 개인 공고가 반드시 추천되는 것은 아닙니다.
